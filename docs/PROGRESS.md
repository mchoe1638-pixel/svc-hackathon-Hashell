## 공동 결정 (합의된 것만)
- 총무는 Android 앱(Capacitor, Vercel 운영 주소를 여는 셸), 동행은 링크로 모바일 웹. 화면 코드는 하나
- 방 만들기는 앱에서만. 총무는 끝까지 앱으로만 사용 (웹과 익명 세션이 따로라 총무 권한이 안 따라감)
- 참여: 이름 고르기 또는 새 이름 추가(OPEN일 때만). 한 이름에 한 기기
- 지출 수정·삭제는 올린 사람·총무만, version 불일치 409. 체크는 기본 전원, 본인만 해제(총무는 대신 가능)
- 정산 확정(SETTLED) 후 쓰기 423, 받는 사람만 '받았어요', 총무만 확정 해제
- 영수증 이미지 저장 안 함. 환율은 현금=방 생성 시 입력, 카드=수출입은행 TTS+수수료(추정 배지)
- 브랜치는 `main`·`backend`(최명규)·`design`(이승화) 세 개만. 각자 자기 브랜치에서 작업하고 세션 끝마다 커밋 하나(메시지에 슬라이스 이름). 슬라이스가 끝나고 vitest·tsc가 통과하면 내 브랜치를 `main`에 병합 (PR·승인 없음). 상대가 병합하면 바로 `main`을 내 브랜치로 받아온다 (공동 계약 변경 직후엔 필수). `main`은 앱이 여는 운영 주소라 병합 후 앱 확인. 미리보기는 내 브랜치 Push 주소, 스크린샷은 메신저로 공유

**2. 상태 전이와 오류 코드**
- OPEN ↔ LOCKED는 초대 링크 열고 닫기다. LOCKED가 막는 건 새 멤버 참여뿐이고 지출·체크는 양쪽 다 된다. 잠금·열기는 총무만(403 `NOT_ORGANIZER`), 이미 그 상태면 성공(멱등), SETTLED면 423 `TRIP_SETTLED`.
- 정산 확정: 총무만, OPEN·LOCKED 어디서나, 이미 SETTLED면 423 `TRIP_SETTLED`. 확정 해제: 총무만, SETTLED → LOCKED, `transfers` 전부 삭제, SETTLED가 아니면 409 `NOT_SETTLED`.
- 받았어요: 받는 본인만(총무도 예외 없음), 아니면 403 `NOT_RECEIVER`. 송금이 없거나 그 여행의 멤버가 아니면 404 `TRANSFER_NOT_FOUND`(둘을 구분하지 않는다), 이미 눌렀으면 처음 시각 그대로 성공. 송금은 SETTLED일 때만 있어서 상태는 따로 보지 않는다.
- 423은 `TRIP_SETTLED`·`JOIN_CLOSED` 두 뜻, 409는 `NAME_TAKEN`·`TRIP_FULL` 두 뜻이다 → 화면은 `status`가 아니라 `error.code`로 가른다.

- 읽기 훅 세 개가 각자 실시간 채널을 연다 (한 화면에서 둘 이상 쓰면 채널이 여러 개). `useExpense`에는 안 붙였다.
- `toggle_share`는 이미 체크된 걸 다시 체크해도 `updated_at`을 올린다 (쓸데없는 이벤트 하나, 무해).
- 읽기 함수(`fetchExpenses`·`fetchExpense`·`fetchSettlement`, SETTLED일 때 확정 송금을 읽는 분기 포함)는 `tsc`만 통과했고 테스트가 없다 (core·라우트만 쓴다는 지시). 확정 송금을 읽는 쿼리의 오류 코드·메시지에 "expense"라는 말이 섞여 있다.
- 브라우저 세션 제공자가 둘(trips·expenses)인 건 그대로다.
- 보안 리뷰(`security-reviewer`)는 속도 모드라 안 돌렸다. 돌린다면 `app/api/trips/`·`app/api/transfers/`·`supabase/migrations/20261103170000_transfers.sql`만 좁혀서.
