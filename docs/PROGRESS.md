# 진행 상황

각자 세션 끝에 자기 칸만 5줄 이내로 갱신한다. (완료 / 다음 할 일 / 막힌 점)

## 공동 결정 (합의된 것만)
- 총무는 Android 앱(Capacitor, Vercel 운영 주소를 여는 셸), 동행은 링크로 모바일 웹. 화면 코드는 하나
- 방 만들기는 앱에서만. 총무는 끝까지 앱으로만 사용 (웹과 익명 세션이 따로라 총무 권한이 안 따라감)
- 참여: 이름 고르기 또는 새 이름 추가(OPEN일 때만). 한 이름에 한 기기
- 지출 수정·삭제는 올린 사람·총무만, version 불일치 409. 체크는 기본 전원, 본인만 해제(총무는 대신 가능)
- 정산 확정(SETTLED) 후 쓰기 423, 받는 사람만 '받았어요', 총무만 확정 해제
- 영수증 이미지 저장 안 함. 환율은 현금=방 생성 시 입력, 카드=수출입은행 TTS+수수료(추정 배지)
- 브랜치는 `main`·`backend`(최명규)·`design`(이승화) 세 개만. 각자 자기 브랜치에서 작업하고 세션 끝마다 커밋 하나(메시지에 슬라이스 이름). 슬라이스가 끝나고 vitest·tsc가 통과하면 내 브랜치를 `main`에 병합 (PR·승인 없음). 상대가 병합하면 바로 `main`을 내 브랜치로 받아온다 (공동 계약 변경 직후엔 필수). `main`은 앱이 여는 운영 주소라 병합 후 앱 확인. 미리보기는 내 브랜치 Push 주소, 스크린샷은 메신저로 공유

- 다음: (사람) `npm install` → `npx vitest run`(핸들러 테스트 3파일·`route.test.ts`는 이 문서 기준 실행 기록 없음) → 통과하면 `backend`에서 커밋 → `main` 병합. 그 뒤 `core/fx.ts`(S4, 카드 환율 임시 계산 대체), S5(읽기 훅 실시간 구독·`transfers` 테이블). 보안 리뷰(`security-reviewer`)는 속도 모드 지시로 건너뜀 — `main` 병합 전에 `app/api/expenses/`·`src/lib/expenses/`만 좁혀 돌릴 수 있음. 정해진 것(유지): EACH/SHARED는 저장만·계산은 SHARED 하나, 차액은 '기타' 품목 한 줄(전원 체크)로 저장(`computeRemainder`), `remainderMemberIds`는 따로 안 둠(core `settlement.ts`의 인자는 아직 남아 있음, 정리 여부 미정), 수정은 전체 교체라 기존 품목은 `id`를 보내야 체크가 유지됨, 통화는 방 통화만, 카드 환율은 S4 전까지 `cashRate`+`cardFeeRate`로 임시 계산(`is_estimated=true`, 고칠 때도 방의 현재 환율로 다시 굳힘), 체크 토글은 `version`을 안 올림, 한도(금액 10억·수량 999·품목 100·보정 10). '기타': 서버만 만들고 지출당 `is_remainder` 품목 최대 1개(DB 부분 유니크), 고치기 요청에 섞인 '기타'는 무시하고 서버가 차액을 다시 계산해 교체(그래서 '기타' id가 바뀌고 체크가 전원으로 초기화됨), 차액 0이면 안 만듦, 이름이 "기타"인 일반 품목은 일반 품목
