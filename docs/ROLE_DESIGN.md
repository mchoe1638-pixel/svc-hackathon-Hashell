# 역할: 디자인·화면 (이승화)

담당: 브랜드, 화면 코드, 공통 컴포넌트, 화면 문구, 데모 준비, 발표 자료.
서버·DB·계산 파일은 수정하지 않는다. 데이터가 더 필요하면 백엔드에게 요청한다.

## 내가 소유한 파일
- `app/page.tsx`, `app/layout.tsx`, `app/globals.css`
- `app/j/[inviteCode]/page.tsx`
- `app/trip/[tripId]/` 아래 모든 `page.tsx`
- `src/components/` (shadcn은 `src/components/ui/`)
- `src/mocks/` 가짜 데이터
- `src/i18n/ko.ts` 화면 문구
- `public/` 로고, 아이콘

## 데이터 쓰는 법 (가장 중요)
- 데이터는 **`src/hooks/`의 훅으로만** 가져온다. `fetch`, Supabase를 직접 쓰지 않는다.
- 처음엔 훅이 `src/mocks/`의 가짜 데이터를 돌려준다. 나중에 백엔드가 진짜 데이터로 바꿔도 내 화면 코드는 그대로다.
- 가짜 데이터는 `src/types/api.ts` 타입을 따라야 한다. 타입이 안 맞으면 빨간 줄이 뜬다.
- 가짜 데이터에 화면 확인용 경우를 일부러 넣는다: 이름이 긴 멤버, 품목 0개, 품목 15개, 금액 큰 숫자.
- 금액은 정수(엔 1단위)로 온다. 화면에서 계산하지 말고 `src/core/money.ts`의 `formatMoney(amount, currency)`로 표시만 한다.
- `app/layout.tsx`에서 앱 전체를 `src/lib/providers.tsx`의 `<Providers>`로 감싼다. 이게 없으면 훅이 동작하지 않는다 (파일은 백엔드가 제공).
- 훅 목록, 쓰는 화면, 상태 필드: `docs/PLAN.md` 5장.

## 모든 화면이 처리해야 하는 상태
| 상태 | 표시 |
| --- | --- |
| 로딩 (`isLoading`) | 스켈레톤 |
| 빈 상태 | 안내 문구 + 다음 행동 버튼 (예: "첫 지출을 추가해보세요") |
| 에러 (`error`) | 짧은 안내 + 다시 시도 |
| 확인 필요 (`needsReview`) | 영수증 결과를 바로 확정하지 않고 수동 확인 화면 |
| 추정 금액 (`isEstimated`) | "추정" 배지 + ⓘ 설명 |

## 화면 목록과 우선순위
| 순위 | 화면 | 파일 | 핵심 |
| --- | --- | --- | --- |
| 1 | 품목 체크 | `trip/[tripId]/expense/[id]/page.tsx` | 체크 한 번에 즉시 반영. 내 몫이 바로 보임 |
| 1 | 홈 | `trip/[tripId]/page.tsx` | 받을 돈 / 보낼 돈 카드 + 지출 목록 + 미참여 배너 |
| 1 | 정산 결과 | `trip/[tripId]/settle/page.tsx` | 송금 목록 (누가 누구에게 얼마), 복사 버튼 |
| 2 | 방 만들기 | `app/page.tsx` | 여행명, 현지통화, 멤버 이름 |
| 2 | 링크 공유 | `trip/[tripId]/invite/page.tsx` | QR + 링크 복사 + 참여 현황 + 잠금 버튼 (모달 아님) |
| 2 | 참여 | `j/[inviteCode]/page.tsx` | 이름 하나 고르기. 잠김이면 마감 안내 |
| 2 | 지출 추가 | `trip/[tripId]/expense/new/page.tsx` | 촬영 / 문자 붙여넣기 / 수기 중 선택 + 결제수단 |
| 3 | 환전 등록 | `trip/[tripId]/fx/page.tsx` | 낸 원화, 받은 외화, 누가 얼마 냈는지 (Day 2 오후, 시간 없으면 드롭) |

순위 1 세 개만 하이파이 디자인을 먼저 잡고, 나머지는 shadcn 기본 컴포넌트로 바로 만든다.

## 디자인 규칙
- 모바일 기준 390×844. PC에서 열어도 최대 폭 480px 가운데 정렬. 라이트 모드만.
- 색·글자·간격·둥글기는 `app/globals.css`의 CSS 변수로 정의하고 Tailwind 클래스로만 쓴다. `#0034B3` 같은 색 코드 직접 사용, `bg-[#...]` 금지.
- 한 화면에 질문 하나, 주요 버튼 하나. 주요 버튼은 하단 고정 + 아이폰 홈 바 여백(`env(safe-area-inset-bottom)`).
- 터치 영역 최소 44px. 입력창 글자 16px 이상 (아이폰 자동 확대 방지).
- 문구는 `src/i18n/ko.ts`에 키로 넣고 `t('home.title')`처럼 쓴다.

## 환경 설정
- `.env.local`에는 `NEXT_PUBLIC_USE_MOCK=true` 한 줄만 둔다. 비밀 키는 받지 않는다.
- 진짜 데이터 연결 확인은 내 컴퓨터가 아니라 PR의 Vercel 미리보기 주소에서 한다.

## 작업 방식
- 브랜치 이름: `ui/home`, `ui/item-check` 처럼 화면 단위.
- PR에는 **폰 화면 스크린샷 필수**. Vercel 미리보기 주소를 폰으로 열어 확인한 뒤 올린다.
- 커밋 메시지: 화면 모양은 `style:`, 새 화면은 `feat:`.
- 처음 쓰는 사람 입장에서 헷갈리는 곳을 발견하면 바로 기록해 공유한다 (UX 테스트 역할).
